## 2. 系统1：聊天室 → 隐藏机会（P0）

### 2.1 概述

聊天室在当前版本中仅为文本交互界面。Phase 2 将其升级为**信息获取渠道**——NPC 在对话中有概率透露影响游戏状态的真实/虚假情报。

### 2.2 触发条件

#### 2.2.1 触发时机

```
信息投放在以下时机触发（不是每次对话都触发，有冷却控制）：

触发点 A：玩家在聊天室主动说话后，AI 回复末尾追加
触发点 B：玩家进入聊天室时，自动刷新 1-2 条闲聊（其中可能含线索）
触发点 C：每天结算日报后，随机 1 条聊天室消息作为"明日风向"展示
```

#### 2.2.2 触发概率公式

```
基础触发概率 = 15%（可配置常量）
智力加成 = 玩家智力技能等级 × 2%
实际触发概率 = min(基础触发概率 + 智力加成, 50%)

冷却机制：
- 同类型信息在 3 个游戏日内不会重复出现
- 每日最多触发 3 条隐藏信息（任意类型合计）
```

#### 2.2.3 信息类型与权重

```c
typedef enum {
    TIP_STOCK_INSIDER,      // 股票内幕消息 — 权重 30
    TIP_LIMITED_TASK,       // 限时打工机会 — 权重 25
    TIP_BLACK_MARKET,       // 黑市限时折扣 — 权重 15
    TIP_HIDDEN_QUEST,       // 隐藏任务线索 — 权重 10
    TIP_EVENT_FORECAST,     // 事件预警 — 权重 10
    TIP_FAKE_TRAP,          // 虚假陷阱（骗局）— 权重 10
    TIP_TYPE_COUNT
} TipType;
```

### 2.4 各信息类型详细设计

#### 2.4.1 股票内幕消息（TIP_STOCK_INSIDER）

**发送者**: 投资大师 / 内部消息 / 刘洋（社交派好友）

**消息模板**:
```
"兄弟，[股票名]这几天有大资金在吸筹。下周[涨/跌]的概率很大。一般人我不告诉他。"
"听说[股票名]要发布重大利好了，懂的都懂。"
```

**真实/虚假判定**:
```
消息真实性 = (发送者是骗子 ? 35% : 70%)
    + (玩家智力 >= 8 ? +15% : 0)
    + (玩家已识破过该骗子 ? +20% : -10%)

如果真实性 >= 50%，消息为真，否则为假。
```

**效果**:
| 消息真假 | 效果 |
|---------|------|
| 真消息：涨 | 该股票当日波动率 +40%，涨的概率 70% |
| 真消息：跌 | 该股票当日波动率 +40%，跌的概率 70% |
| 假消息：涨 | 该股票当日波动率 +60%，跌的概率 80%（诱多） |
| 假消息：跌 | 该股票当日波动率 +60%，涨的概率 80%（诱空） |

**持续时间**: 仅当日有效（当天股市收盘后清除效果）

**反制机制**：
- 智力检定：玩家智力 >= 6，聊天室显示 `[? 智力检定：你觉得这话有7成可信]`
- 智力 >= 10，显示 `[? 智力检定：可信度约85%——"内部消息"这人以前骗过你，小心]`
- 玩家可选择 `[1] 相信并操作` / `[2] 忽略` / `[3] 反向操作（需要智力>=12）`

**防滥用措施**:
```
1. 每个股票每天只能被 1 条内幕消息影响
2. 同一天内最多 2 条股票内幕消息
3. 内幕消息产生的额外波动不计入玩家持股的被动收益（仅影响主动交易）
4. 如果玩家连续 3 次相信假消息亏损 > 3000，触发成就"人精"进度
```

#### 2.4.2 限时打工机会（TIP_LIMITED_TASK）

**发送者**: 路人甲 / 小明 / 小红 / 李华 / 刘洋 / 周梅

**消息模板**:
```
"城东那边有个急活，搬货一天给三倍工资。只招今天。"
"XX公司在招临时程序员，日结，比平时多一倍。有没有人一起去？"
"明天有个会展需要工作人员，一天800，管饭。"
```

**真实/虚假判定**:
```
限时任务几乎总是真的（90%），但可能是骗子伪造的"高薪陷阱"（10%）：
- 路人甲/小明/小红/李华/周梅发 → 100% 真实
- 投资大师/内部消息/神秘人发 → 50% 真实（可能是陷阱）
```

**效果**:
| 情况 | 效果 |
|------|------|
| 真实限时任务 | 当日解锁一个临时打工选项，收入为常规任务 1.5-3.0× |
| 虚假高薪陷阱 | 打工失败率 90%，且可能被额外骗走 200-500 坤币 |

**新增限时打工池**（控制台只需新增任务结构体）:
```c
// 限时打工任务池（6种模板）
typedef struct {
    char name[50];
    char description[150];
    int base_income;         // 基础收入
    int required_level;
    int time_slot_cost;      // 消耗时间槽数（通常1，高收益的2）
    int difficulty_bonus;    // 限时加成的额外百分比
    SkillType bonus_skill;   // 关联技能（有技能加成）
    bool is_trap;            // 是否是陷阱任务
} LimitedTask;
```

限时打工模板：
| 任务名 | Lv | 基础收入 | 时限加成 | 时间槽 | 描述 |
|--------|-----|---------|---------|--------|------|
| 搬货急单 | 1 | 50 | +200% (共150) | 1 | "城东仓库清仓，按件计费" |
| 会展临时工 | 3 | 200 | +150% (共500) | 1 | "会展中心周末活动招人" |
| 私活外包 | 8 | 500 | +120% (共1100) | 2 | "李华介绍的私活——比上班赚得多" |
| 活动安保 | 5 | 300 | +100% (共600) | 1 | "坤城音乐节临时安保" |
| 高端家教 | 10 | 800 | +80% (共1440) | 1 | "富人区需要高中数理化家教" |
| 应急翻译 | 12 | 1000 | +60% (共1600) | 1 | "国际会议需要临时翻译" |

**反制**: 陷阱任务的 NPC 发消息时，如果玩家智力 >= 5，消息文本中包含细微破绽（如"工资日结"但要求先交 200 保证金）。

#### 2.4.3 黑市限时折扣（TIP_BLACK_MARKET）

**发送者**: 神秘人 / 深夜司机

**消息模板**:
```
"有批货，今天特价。要不要？"
```

**效果**: 商城出现 1 个限时物品（当日有效），折扣 30%-50%。物品类型：
- 宠物食品（概率 40%）
- 稀有家具（概率 30%）
- 神秘钥匙（概率 20%）
- 垃圾赝品（概率 10%，描述与真品相同但功能减半）

**反制**: 玩家魅力 >= 8 时可以"讨价还价"，额外获得 10% 折扣。购买后神秘人好感度 +5。

#### 2.4.4 隐藏任务线索（TIP_HIDDEN_QUEST）

**发送者**: 老陈 / 周梅 / 赵磊

**消息模板**:
```
"老城区那边有栋楼，据说地下室里藏着什么东西……"
"昨天采访了一个人，他说坤城北边有个废弃工厂里有些值钱的东西。"
```

**效果**: 解锁一个隐藏任务（Quest 系统中新增 QUEST_SPECIAL 子类型），完成后获得：
- 坤币 2000-5000
- 神秘钥匙 ×1
- 特殊成就进度

**隐藏任务池**（3个）:
| 任务名 | 触发线索 | 完成条件 | 奖励 |
|--------|---------|---------|------|
| 老城区地下宝库 | 老陈 | 打工 10 次 + 探索 3 次 | 坤币 3000 + 神秘钥匙 ×1 |
| 废弃工厂秘密 | 周梅 | 精神>=70 + 打工出租车 5 次 | 坤币 5000 + 隐藏家具"老式留声机" |
| 赵磊的特殊委托 | 赵磊 | 声望>=3 + 智力/魅力检定 | 坤币 4000 + 公司免费升1级 |

**反制**: 隐藏任务如果接了但在 7 天内未完成，NPC 会失望，好感度 -10。

#### 2.4.5 事件预警（TIP_EVENT_FORECAST）

**发送者**: 老陈 / 周梅 / 路人甲

**消息模板**:
```
"听说明天要有暴雨，我关节开始疼了。"
"气象台那边有消息，下周可能有台风。"
```

**效果**: 提前 1-3 天预告日报事件（将原本随机决定的事件变为确定），让玩家提前规划。

预警准确率：
- 老陈：80%
- 周梅：95%
- 路人甲：50%

反制：如果预警错误（预告事件没发生），老陈的下一句对话会自嘲"我这老骨头不中用了"，周梅会发澄清消息。

#### 2.4.6 虚假陷阱（TIP_FAKE_TRAP）

**发送者**: 投资大师 / 内部消息

**设计意图**: 不是所有聊天室信息都对玩家有利。骗局是叙事的一部分，也是玩家学判断力的机会。

**陷阱类型**:
| 陷阱 | 描述 | 损失 |
|------|------|------|
| 假股票消息 | 诱导买入即将暴跌的股票 | 可能亏损 20-50% 投入资金 |
| 假招聘 | 收取保证金后消失 | 损失 300-800 坤币 |
| 假优惠 | 商城的"限定"物品其实是普通品 | 溢价 50% 购买 |
| 钓鱼链接 | "点这个链接领红包" | 盗取当前持有坤币的 5%（最低 100） |

**识别机制**:
```
玩家识破条件（满足任一）：
1. 智力 >= 7 自动识破，消息显示为红色 + "[? 骗子]"
2. 之前被同一 NPC 骗过 2 次，第 3 次自动识破（"事不过三"）
3. 魅力 >= 10 可以从语气判断（"这话术太标准了"）

识破后：
- 成就"人精"进度 +1
- 骗子对该玩家的诈骗频率降低 50%
- 聊天室出现 "[系统] 投资大师 被多人举报为骗子"（概率 30%）
```

## 3. 系统2：宠物协助打工（P1）

### 3.1 概述

宠物从纯被动收入加成升级为**主动协助机制**——每种宠物有自己的协助方式和触发条件。协助不是免费的：消耗宠物心情/饱食度，需要玩家投入资源维护。

### 3.2 触发条件

#### 3.2.1 触发时机

```
触发入口：玩家每次打工前，在打工确认界面增加选项：
  "[? 宠物] 派遣小咪协助你打工（消耗小咪 20 心情，成功率+15%）"

触发条件：
1. 宠物已解锁且心情 >= 30
2. 宠物饱食度 >= 20
3. 打工任务匹配宠物的协助类型（见 3.3）
4. 同一时间槽只能派遣 1 只宠物
5. 同一宠物每天最多派遣 2 次
```

#### 3.2.2 宠物状态影响

```
宠物心情公式：
  心情恢复 = 每天 +5（自然恢复）+ 喂食 +10（如果用宠物食品）+ 玩耍 +15
  心情消耗 = 打工协助 -20 + 未喂食 -10/天
  
宠物饱食度公式：  
  饱食度消耗 = 自然消耗 -5/天 + 打工协助额外 -10
  饱食度恢复 = 喂食 +30（普通食物）/ +50（宠物食品）
```

## 4. 系统3：好友组队系统（P2）

### 4.1 概述

高好感度好友可以"组队"打工——好友陪伴玩家完成一次打工，提供加成。但好友不是无限使用的：消耗好友的"行动点数"和玩家好感度。

### 4.2 触发条件

#### 4.2.1 组队前置条件

```
必要条件（全部满足）：
1. 好友好感度 >= 30（friendship_level >= 3.0）
2. 好友在线（is_online == true）
3. 好友当日尚未被组队超过 1 次
4. 玩家当日组队次数 < 2 次

增强条件（提升效果）：
1. 好友好感度 >= 70（friendship_level >= 7.0）→ 组队加成 ×1.5
2. 好友职业与玩家打工类型匹配 → 额外触发"默契加成"
3. 玩家与好友同属一个职业路线 → 额外 +10% 收入
```

#### 4.2.2 好友"行动点数"

```
每个好友每天有 1 个"行动点数"= 可以被组队 1 次。
特殊：好感度 >= 80 的好友，每天有 2 个行动点数。

组队消耗：
- 基础消耗：好感度 -2（临时，打工后如果成功则恢复1，净消耗1）
- 打工失败：好感度额外 -5（"跟你组队害我也失败了"）
- 好友行动点数 -1
```

### 4.3 组队加成计算

#### 4.3.1 基础加成公式

```
组队收入加成 = 基础加成 × 好感度系数 × 职业匹配系数

基础加成（按好友角色）：
  小明（出租车老油条）：+12% → 出租车/外卖/配送类
  小红（外卖拼命三娘）：+15% → 外卖/跑腿/体力类
  小刚（莽撞伐木工）：+10% → 体力/伐木/探险类
  李华（快乐程序员）：+15% → 程序员/交易/智力类
  王芳（连续创业者）：+12% → 公司经营/投资类
  张伟（竞争老板）：+8%（竞争关系反而加成低）
  刘洋（八面玲珑中介）：+12% → 销售/房产/社交类
  陈静（销售女王）：+18% → 社交/谈判/魅力类（最佳组队伙伴）
  赵磊（神秘掮客）：+20%（但每次组队有10%概率触发灰色事件）
  周梅（记者）：+10% → 任意类型（全能但加成不高）

好感度系数：
  好感30-49：×1.0
  好感50-69：×1.2
  好感70-89：×1.5
  好感90-100：×2.0（满好感好友是最强助力）

职业匹配系数：
  好友职业标签与打工类型完美匹配：×1.0
  好友职业标签与打工类型部分匹配：×0.7
  好友职业标签与打工类型不匹配：×0.4
```

```
 [1] '行，你帮我联系。'— 收入额外 +200，但需要李华好感 >= 60
 [2] '这是公司的代码，不太好。'— 李华好感 +5，解锁成就"技术无罪"进度
 [3] '先问问老板。'— 魅力检定，成功则两全其美（收入+100 且好感 +3）
```

## 5. 系统4：每周挑战系统（P2）

### 5.1 概述

对标 GDD §7.3，每周（7个游戏日）自动生成一个随机挑战目标。完成挑战获得奖励。周日结算时评估完成情况并刷新新挑战。

### 5.2 触发条件

#### 5.2.1 周重置时机

```
重置时机：每个第 7 天（day_count % 7 == 0）的日报结算之后
首次触发：玩家 day_count >= 7 时产生第一个周挑战

重置流程：
1. 周日日报显示 → "本周挑战结算"
2. 结算上周挑战（完成/未完成）
3. 如果完成 → 发放奖励 + 展示成就进度
4. 随机生成下周挑战（从可用池中排除上周类型）
5. 日报"明日预告"展示新的周挑战
```

#### 5.2.2 挑战可用性条件

```
挑战类型 pool 里的每个挑战有解锁条件：
- 玩家等级 >= 挑战要求等级
- 特定系统已解锁（如股票、公司、宠物）
- 上一周的挑战类型 != 本周类型（避免连续同类型疲劳）
```

## 7. 实现优先级与建议顺序

### 7.1 实现顺序

## 8. 风险清单

| 风险 | 严重度 | 缓解措施 |
|------|--------|---------|
| 聊天室信息过多导致玩家疲劳 | 低 | 每日上限 3 条 + 冷却机制保证稀缺性 |
| 宠物协助使游戏过于简单 | 中 | 消耗机制（心情/饱食度）限制使用频率；每日上限 |
| 组队加成叠加后数值膨胀 | 中 | 加法叠加 + 系数上限 0.5 |
| 每周挑战让玩家感到强迫 | 低 | 不完成无惩罚；挑战可选；失败只影响连胜 |
| 数据结构膨胀（Player 结构体过大） | 中 | 新增字段总计约 500 字节，在可接受范围（当前 Player ~8KB） |
| 控制台 UI 信息过载 | 低 | 打工确认界面按优先级分段展示，用分隔线区分模块 |
| 旧存档兼容性 | 高 | SAVE_VERSION 升级到 8；新增字段有安全默认值；提供存档迁移函数 |

## 附录 A：SAVE_VERSION 升级方案

```c
// Phase 2 将 SAVE_VERSION 从 7 升级到 8
#define SAVE_VERSION 8

// 存档迁移函数
void migrate_save_v7_to_v8() {
    // 所有 Phase 2 新增字段初始化为安全默认值
    player.active_tip_count = 0;
    player.tips_generated_today = 0;
    for (int i = 0; i < TIP_TYPE_COUNT; i++) player.tip_cooldown[i] = 0;
    player.daily_limited_task_count = 0;
    player.today_team_count = 0;
    player.chal_streak = 0;
    player.chal_total_completed = 0;
    player.weekly_income_buff = 1.0f;
    player.weekly_buff_remaining = 0;
    
    // 宠物新增字段
    for (int i = 0; i < MAX_PETS; i++) {
        player.pets[i].assist_count = 0;
        player.pets[i].assist_success = 0;
        player.pets[i].today_assist_count = 0;
        player.pets[i].ability_flags = 0;
    }
    
    // 好友新增字段
    for (int i = 0; i < MAX_FRIENDS; i++) {
        player.friends[i].daily_action_points = 1;
        player.friends[i].max_daily_points = 1;
        player.friends[i].career_tag = (i < 3 ? 0 : (i < 6 ? 1 : 2));
    }
}
```

## 附录 B：设计决策日志

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 聊天室信息真实性判定 | 全随机 vs 基于NPC+智力 | 基于NPC+智力 | 符合GDD"分辨真假需要智力检定" |

| 组队加成计算 | 乘法叠加 vs 加法叠加 | 加法叠加（上限0.5） | 防止数值膨胀；简单可预期 |
| 周挑战失败惩罚 | 有惩罚 vs 无惩罚 | 无惩罚（仅中断连胜） | 避免给玩家压力感；正向激励为主 |
| 挑战类型防重复 | 上周排除 vs 近3周排除 | 上周排除（仅1周） | 保留随机性，12种类型够丰富 |
